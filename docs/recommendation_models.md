# 추천 모델 설계 및 평가 보고서

Steam 유저 맞춤 게임 추천 — 콘텐츠/협업 필터링 기반 4개 모델 + NDCG 평가

## 1. 개요

유저의 Steam 플레이 데이터와 게임 속성을 결합해 "이 유저가 아직 안 한 게임 중
좋아할 만한 것"을 Top-N으로 추천한다.

**역할 분담**

| 담당 | 모델 |
|---|---|
| 현빈 | 인기도, 콘텐츠 기반, User-CF, Item-CF |
| 가윤 | SVD, MAB |

모든 모델은 동일한 NDCG 평가로 비교하며, 가윤의 모델도 같은 인터페이스로 합류한다.

## 2. 데이터

| 파일 | 정체 | 단위 |
|---|---|---|
| `cleaned_data.csv` | 유저가 **보유**한 모든 게임(0시간 포함) | 유저×게임 행 |
| `cleaned_played_data.csv` | 위에서 **0시간 제거**(실제 플레이) — 모델·평가의 기본 입력 | 유저×게임 행 |
| `game_features_full.csv` | 게임 42차원 속성(장르 12 + 태그 30) + 수치형(평점·가격·리뷰수 등) | 게임 행 |
| `user_genre_preference_normalized_clean.csv` | 유저별 장르 취향 비중(합=1) | 유저 행 |
| `user_tag_preference_top30_normalized_clean.csv` | 유저별 태그 취향 비중(합=1) | 유저 행 |

**모델별 사용 파일**

| 모델 | 사용 파일 |
|---|---|
| 인기도 | `cleaned_played_data.csv` (게임별 플레이 유저 수) |

| User-CF / Item-CF | `cleaned_played_data.csv` (유저×게임 행렬) |

**전처리 공통**: 플레이타임 `log(1+x)` 변환(극단값 완화), 이미 보유한 게임은 추천에서 제외.

## 3. 추천 모델 4종

### ① 인기도 (Popularity) — baseline

- **정의**: 게임을 플레이한 고유 유저 수가 많을수록 높은 점수. 개인화 없음(모두 동일).
- **과정**: `groupby('appid')['steamid'].nunique()` → 점수순 정렬 → 보유 제외 → Top-N
- **역할**: 다른 모델이 반드시 넘어야 하는 기준선.

### ② 콘텐츠 기반 (Content) + Value Score

- **정의**: 유저 취향벡터와 게임 속성(장르·태그)의 코사인 유사도로 "취향이 닮은 게임" 추천.
- **과정**
  1. 취향벡터(장르 12 + 태그 30 = 42차원) ↔ 게임 벡터(같은 42차원) **코사인 유사도**
  2. **Value Score**로 동점 보정: `점수 = 0.6·유사도 + 0.2·평점 + 0.2·인기도` (각 항 0~1 정규화)
  3. 보유 제외 → Top-N
- **수치형 feature 방침**: 평점(rating_by_reviews)·인기도는 Value Score 항으로 사용. **가격·메타크리틱은 제외**(가격은 품질 신호가 아니고, 메타크리틱은 결측이 많음).
- **한계**: 장르·태그만으론 같은 프로필 게임을 구별 못 함(동점) → Value Score가 이를 완화.

### ③ 유저 기반 CF (User-CF)

- **정의**: "나와 비슷하게 플레이한 사람들"이 즐긴 게임 추천.
- **과정**
  1. 유저×게임 행렬(값=로그 플레이타임) → **유저-유저 코사인 유사도**
  2. 가장 비슷한 이웃 K=20명 선택
  3. 게임점수 = Σ(이웃 유사도 × 그 이웃의 게임 플레이타임) → 보유 제외 → Top-N

### ④ 아이템 기반 CF (Item-CF)

- **정의**: "내가 한 게임과 같이 플레이되는 게임" 추천. User-CF와 축이 반대(게임끼리의 관계).
- **과정**
  1. 유저×게임 행렬을 **전치**해 **게임-게임 코사인 유사도**
  2. 게임점수 = 유저의 플레이 벡터 · 게임유사도 행렬 → 보유 제외 → Top-N
- **비고**: 행렬 하나로 User-CF·Item-CF 둘 다 계산된다.

## 4. 평가지표 — NDCG

랭킹 기반 추천 평가지표. 단순히 "맞췄나"가 아니라 **"좋아할 게임을 얼마나 위에·순서대로 올렸나"**를 잰다. relevance로 **로그 플레이타임**을 써서, 오래 즐길 게임을 위에 둘수록 점수가 높다.

- **CG (Cumulative Gain)**: relevance의 단순 합. 순서 무시.
- **DCG (Discounted CG)**: 순위 할인 적용. `DCG = Σ relevance_i / log2(i+1)` (위에 있을수록 덜 깎임)
- **IDCG (Ideal DCG)**: 정답을 relevance 높은 순으로 완벽 배치했을 때의 DCG = 만점.
- **NDCG = DCG / IDCG**: 유저마다 아이템 수·크기가 달라 DCG는 직접 비교가 어렵다. IDCG로 나눠 0~1로 정규화하면 크기에 상관없이 비교할 수 있다.

**평가 절차 (hold-out)**

1. 각 유저의 플레이 게임 중 30%를 숨김(test=정답, relevance=로그 플레이타임), 70%로 모델 구성.
2. 모델이 안 가진 게임 전체를 점수순 정렬.
3. 숨긴 정답을 얼마나 위에 올렸는지 **NDCG@10 / Recall@10** 계산.
4. 전체 유저 평균 → 모델 점수.

**공정성 규칙**: 모든 모델이 같은 분할·같은 후보군·같은 relevance 사용, test 게임은 학습에 절대 미포함(누수 방지), 평가 코드는 팀 공유.

> 추천 시스템의 NDCG는 후보(수천 개) 중 정답(수 개)을 top-10에 올리는 문제라 절대값이
> 낮게 나온다(0.1~0.3이면 준수). **절대값이 아니라 인기도 baseline 대비로 판단**한다.

## 5. 중간 실험 결과

779명, hold-out 30%, seed=42 기준 (`results/model_comparison.csv`).

| 모델 | NDCG@10 | Recall@10 |
|---|---|---|
| **Item-CF** | **0.2150** | 0.1704 |
| User-CF | 0.1905 | 0.1441 |
| 인기도 (baseline) | 0.1543 | 0.1248 |
| 콘텐츠 (+Value Score) | 0.0883 | 0.0703 |

**해석**

- **Item-CF가 가장 우수** — 게임끼리의 공동 플레이 관계가 이 데이터에서 가장 강한 신호.
- **협업 필터링(Item/User-CF)이 인기도 baseline을 넘음** — 개인화가 실제로 작동.
- **콘텐츠는 Value Score로 개선됨** (순수 유사도 0.027 → 0.088, 약 3배). 다만 아직 baseline 미만이라, 장르·태그 표현의 한계(같은 프로필 게임 구별 어려움)가 남는다.
- 데이터 특성(99% 희소, 게임 47%가 1인 보유)상 콘텐츠 단독보다 **CF·하이브리드가 유리**하다는 것이 수치로 확인됨.

## 6. 향후 개선 (메모)

- **콘텐츠 Value Score에 가격(δ)항 추가** 후 NDCG 변화 테스트 *(예정)*
- 하이브리드(콘텐츠+CF) 가중치 튜닝으로 CF 단독 넘기
- `recent_playtime_hours`(최근 2주)로 현재 취향 반영 실험
- 분할 seed 여러 개 평균(교차검증)으로 수치 안정화
